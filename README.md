# Парк «Сказка» — исследование и хакатон-проект

Репозиторий состоит из двух частей:

1. **Исследовательский пакет** — аналитическая база по парку развлечений «Сказка» (Москва, ул. Крылатская, 18, [parkskazka.com](https://parkskazka.com/)): сбор отзывов из открытых источников, контент-анализ официального сайта, тематическая разметка отзывов и иллюстративные промты.
2. **[v1/Хакатон 2026/](v1/Хакатон%202026/)** — прототип игры «Хранитель Сказки» (команда WIDE, кейс 09 «Парк „Сказка“»), построенный на основе этого исследования.
3. **[DESIGN.md](DESIGN.md) + [design/landing/](design/landing/index.html)** — визуальный стиль в духе parkskazka.com (палитра, типографика, компоненты) и демо-лендинг для согласования; общий стиль-код для будущих материалов проекта.

**Дата сбора и анализа:** 20 октября 2026 г.
**Метод:** автоматический обход открытых страниц + ручная разметка ~60 развёрнутых отзывов за 2016–2026 гг. по темам и тональности.

## Игра «Хранитель Сказки» (v1)

Онлайн-квест по парку «Сказка» с ИИ-ведущим — котом Баюном. Первый экран — планировщик визита «План»: топ-7 аттракционов → состав группы по росту → вопросы Баюну → маршрут дня с учётом погоды → бонусные задания по пути (кафе, коды наград). Дальше: статусы аттракционов и причины остановок, рейтинг любимых аттракционов, голосование за ремонт, конструктор новых аттракционов, мини-стратегия на 5 ходов.

- **Запуск:** `v1/Хакатон 2026/run_game.bat` (или `python server.py` в этой папке) → http://localhost:5173, вкладка «Игра».
- **ИИ-ведущий:** ключ в файле `host_key.txt` рядом с `server.py` или в переменной окружения `HOST_API_KEY`; без ключа ведёт «резервный ведущий» с готовыми сценами. Подробности — в [`КАК_ЗАПУСТИТЬ.txt`](v1/Хакатон%202026/КАК_ЗАПУСТИТЬ.txt).
- **Внутри папки:** `landing/` — одностраничный лендинг кейса; `v1/` — ранний прототип «Сказка: когда идти и что делать»; `Презентация/` — питч команды (PDF/PPTX); `01-исследование-парк-Сказка.md` — краткое исследование для ИИ-агента.

## Развёртывание сайта с Баюном (docker compose)

Бэкенд Баюна ставится на сервер одной командой; статику раздаёт ваш nginx.

1. `cp runner/.env .env` — ключ `QWEN_API_KEY` рядом с [`docker-compose.yml`](docker-compose.yml) (файл в .gitignore).
2. `docker compose up -d --build` — контейнер `bayun` (healthcheck на `/health`) подключается к внешней docker-сети `ai-net`.
3. В конфиг своего nginx добавьте `location` из [`deploy/nginx-bayun.conf.example`](deploy/nginx-bayun.conf.example) — страница откроется на `/bayun/` сайта (SSE уже учтён: прокси без буферизации).
4. Плавающая кнопка «🐈» на страницах открывает чат Баюна в панели (страница открывается с `?embed=1` — сразу чат, без шагов планирования); адрес переопределяется `window.BAYUN_URL`, на сайте защиты можно выключить виджет, задав `window.BAYUN_URL = ''`.

### Что отдаёт контейнер

- `GET /bayun/` — одностраничный сценарий «спланируй визит → спроси Баюна»: шаг 1 «Визит» (дата + состав группы: имена и рост), шаг 2 «Интересы» (топ-7 аттракционов с проверкой по росту), шаг 3 «Маршрут» (автогенерация плана дня по часам: детские и спокойные точки до обеда, экстрим после, обед в 13:00), шаг 4 — чат с Баюном. Конфигурация гостей и маршрут передаются боту с каждым вопросом (`context` в `POST /api/chat`), а при входе в чат заявка визита сохраняется в хранилище (`POST /api/visits`).
- `GET /bayun/dashboard` — дашборд маркетинга: категории групп (семья с детьми / взрослая компания / детская группа), топ аттракционов, даты визитов, сегменты гостей по росту, построенные маршруты, последние заявки с планом дня и полный диалог (вопросы гостей + ответы Баюна). Если задана переменная `DASHBOARD_TOKEN`, данные `/api/stats` отдаются только с этим токеном (`?token=…`, страница спросит его сама). Заявки и диалог хранятся в JSONL-файлах на томе `bayun_data` — переживают пересборку контейнера.
- `POST /bayun/api/chat` — чат (SSE): `{ message, history?, context?: { visitId?, date?, group?, picks?, route? } }`; без `context` работает как раньше. В `dialogue.jsonl` пишутся обе реплики: вопрос гостя и ответ Баюна.

Статика для nginx: лендинг — `v1/Хакатон 2026/landing/`, игра — `index.html`, `*.js` и `style.css` из `v1/Хакатон 2026/`, сайт защиты — `v1/Хакатон 2026/Защита/Команда — Хранитель Сказки/`, виджет погоды — `v1/Хакатон 2026/weather/`. Игра на статике работает с резервным ведущим, живой Баюн доступен через `/bayun/`.

## Ключевые выводы (кратко)

- **Разрыв рейтингов:** Яндекс.Карты — 5,0 (51 711 оценок) против 3,7 на Отзовике и ~3,6 на IRecommend. «Карточные» оценки отражают узнаваемость бренда, развёрнутые тексты — реальный опыт визита.
- **Продукт сильный, экономика визита — нет:** масштаб, тематические парки (Дино парк, Хаски Лэнд) и территорию хвалят стабильно; жалобы №1 — цены (семейный чек 5–9 тыс. ₽) и очереди.
- **Самый токсичный тип негатива** — не дороговизна, а ощущение обмана: «безлимит» с ограничениями, обнуление проходов на карте парка.
- **Динамика:** негатив сместился от «детских» тем (сервис, мелочи, 2017–2021) к системным (цена/ценность, прозрачность тарифов, 2024–2026) — синхронно с ростом цен.

## Ограничения данных

- Полные тексты отзывов Яндекс.Карт, Tripadvisor и 2ГИС закрыты от автоматического чтения — по ним сохранены сниппеты и агрегаты.
- Отзовик: сохранена первая страница (40 из 158 отзывов); распределение оценок — по видимой части.
- Частотность тем — экспертная, а не алгоритмическая; цены и даты приведены дословно из отзывов и не проверялись.
- Актуальность цен и режима работы: [официальный сайт](https://parkskazka.com/) и [прайс-лист](https://parkskazka.com/pricelist/).
